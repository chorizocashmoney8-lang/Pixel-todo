# Pixel Todo 开发与维护

这份文档面向开发者、维护者和协助修改项目的 AI。产品介绍与使用入口见 [README](../README.md)。当前软件版本为 **1.0.0**。

功能包括角落小窗/托盘、待办与回收站、25+5分钟番茄钟、手动立即完成、统计、7套像素主题及角色、字体和声音设置。全部数据存储在本机。

## 双击启动

- 本机已有依赖时,双击 `启动软件.cmd`,无需打开Git Bash。
- 双击 `创建桌面快捷方式.cmd`,创建名为“Pixel Todo（源码版）”的桌面快捷方式;不会覆盖安装版快捷方式。源码文件夹移动后需重新创建快捷方式。
- 安装版日常使用直接点击桌面“Pixel Todo”,无需源码目录或Node开发环境。
- 同时打开源码版和安装版时,单实例机制通常会激活已经运行的那个版本。要切换版本,先在托盘退出。

## 数据与Git

本机正常运行数据目录为 `%APPDATA%\pixel-todo-desktop\`,主文件为 `pixel-todo.json`,升级备份为 `pixel-todo.json.v3.bak`,导入声音位于其中的 `sounds/`。该目录位于源码仓库之外,因此在源码仓库执行 `git add .` 不会包含这些个人数据。不要手动把个人数据复制进仓库。环境变量 `PIXEL_TODO_TEST_DATA` 可为开发验收指定独立目录。

## 开发

在此目录执行(当前工程使用Node.js 24)：

```bash
npm ci
npm test
npm start
npm run dist
```

`dist-build/`包含当前构建产物,Windows安装包为 `Pixel Todo Setup 1.0.0.exe`。打包复用已安装的Electron运行时并使用系统证书库;不关闭TLS校验。

## 目录

- `main/`:计时、JSON持久化、窗口、托盘和音频导入。
- `preload/`:页面有限API。
- `renderer/`:完整窗口、小窗、提醒和共享主题/角色。
- `assets/`:本地音频、字体和应用图标。
- `test/`:Node自动测试。
- `docs/`:本次1.0.0对应的需求/技术设计快照。

## 升级与数据

保留原数据文件位置;v3升级为v4,首次升级时创建 `pixel-todo.json.v3.bak`。用户数据不放在源码仓库中,重新构建不会清空待办。

安装前从托盘退出旧版。开发检查通过独立数据目录运行,不会读取个人待办。

## Git

源码、测试、资源、package.json和锁文件需要纳入版本控制。`node_modules/`、`dist/`、`dist-build/`和本地配置由`.gitignore`排除。安装包使用GitHub Release附件发布,不加入普通Git提交。

## 资源

Fusion Pixel字体采用OFL-1.1,许可证见 `assets/fonts/OFL.txt`。角色使用本项目已确认的像素素材;三种内置提示音为本项目原创合成音频。待办页仅使用一行有署名的现代诗。

## 修改项目之前

- 产品需求见 [PRD.md](PRD.md)，技术结构见 [TECH_DESIGN.md](TECH_DESIGN.md)。先读与本次改动相关的部分，再检查源码。
- 保留现有产品行为，修改后做相关验证；用户个人数据与验收数据分开。
- `build/installer.nsh` 是安装器源码，应纳入 Git；`dist-build/` 是打包产物，应忽略。
- `docs/images/` 是仓库首页需要的产品预览图，应该与 README 一起提交。预览使用演示数据，不含个人待办。
- 文档修改不需要重打安装包；应用代码或打包配置变化后，才重新构建并验证相应结果。

## 文档与源码边界

`README.md` 面向潜在使用者；本文件面向开发和维护。两者都随源码保存，不需要另建一份隐藏的 AI README。AI 也应结合需求、技术设计与实际源码理解项目。

本机交付目录在独立源码仓库之外。正式源码以当前仓库的 Git 提交为准；对外分享源码可使用仓库页面的下载功能，安装包作为 Release 附件单独发布。不要为了共享再维护一套分叉的源码副本。
